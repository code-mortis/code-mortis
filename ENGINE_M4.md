## 2. Reliability, scope and performance contracts

- Every request belongs to a durable, currently owned job. Review stages also require the matching stage claim; retries require the matching retry job. Replaced claims, expired leases, changed credentials/connections, disabled users/repositories/installations, revoked MCP/PAT origins and changed PR revisions cannot dispatch or accept late results.
- Fresh external authorization occurs before inference and before result acceptance. Local admission checks avoid repeated GitHub calls while waiting for capacity. Shared admission still enforces the stricter connection/run limits; there is no provider/model/connection fallback.
- Analysis, assessment, verification and summary retain separate immutable token allowances. All security AI phases share the scan's security allowance. Caller remaining allowances cannot borrow from a larger plan cap. Known usage is additive across repair/evidence rounds; unknown usage blocks new work under that allowance. Reservations are not reported as observed tokens.
- Request schemas are strict, and existing workflow validators still decide whether evidence supports a result. Invalid output can produce sanitized structured feedback for bounded correction; raw provider output, repository source and reasoning are not added to durable task results. All persisted validated results pass redaction first.
- Assessment checks the current history identity again before accepting a result. Verification checks that the finding remains open and its synchronization version has not changed. Absence from a later analysis remains **not observed**, never an automatic fix. Exact repeats reuse the existing identity without a fresh semantic assessment.
- PR supporting sources use neutral Git reads at exact base/head identities and the same mandatory/additional exclusions and trusted-rule precedence as M3. Both rename sides are checked. Required-source limits fail explicitly; optional graph context cannot broaden scope or reduce baseline coverage. Scanner evidence keeps its separate policy, including dependency files required for security analysis.
- Code graph compatibility remains `graph-context/v2`: exact revision, extractor and policy identities, bounded optional evidence and existing origin permissions. No graph schema/index migration or new graph dependency is introduced. Original/current evidence used by assessment and verification remains distinct.
- Completed ledger tasks replay after a recoverable worker attempt without another model call. Assessment/verification can resume their saved requests; scanner recovery retains the original plan and refuses unknown-consumption replay. Saved results remain useful after publication retries without reanalysis.
- Interrupted summaries and project background remain conservative: unfinished inference fails explicitly and requires an explicit new attempt; it does not automatically obtain a new allowance. A saved completed summary is recovered into a terminal pipeline stage. This preserves prior behavior and prevents an interrupted summary from leaving the parallel finalizer waiting forever. Broader crash-window recovery is part of M5.
- Summary timeouts also apply to inline execution where the original PR plan has no summary deadline. Preparation, capacity waits and transport retries consume the same caller deadline. Immutable plan deadlines cannot be extended by a later call. Background queue expiration remains distinct from its inference timeout.
- M3 keeps its shared HTTP pool and bounded parallel analysis queue. M4 retains existing workflow concurrency and M2 admission, with one HTTP client per structured workflow invocation; cross-invocation pooling is not claimed. Additional ledger/authorization work and connection setup must be measured in M5 before claiming a speedup.
