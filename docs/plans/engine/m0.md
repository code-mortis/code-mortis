## 7. Subscription retirement inventory and M1 decisions

Retirement is an intentional target change, so the existing native branches are not M0 bugs. The inventory below identifies where M1 must enforce the new boundary and which historical/general-purpose behavior must remain.

Freeze these M1 design decisions:

1. Reject non-API/unknown connection kinds at shared admission and every deferred execution boundary, not just write schemas. Keep historical output/storage readers permissive enough to read existing records without a runner.
2. Use a planned cancellation cutover for queued/active native inference. Preserve validated outcomes, partial publication and unknown usage; no background native consumption is allowed after the cutover. Operational execution is M1 work, not performed by this audit.
3. Fence old binaries operationally: stop old admission/consumers, settle/cancel native tasks, invalidate the old runner credential/reachable inference endpoint, and restart only updated components. Leases alone cannot prevent old code from making requests. Keep cancellation/logout cleanup separate from permission to start inference; backup restoration must not reactivate the old path.
4. Preserve an affected repository's old connection reference as historical/remediation data. Exclude it from executable choices and return an actionable retired-connection state; do not auto-select a shared connection. Unrelated setting edits and disabling a repository must still work without reauthorizing a retired grant.
5. Preserve explicit summary regeneration as a product feature: if an administrator has selected a shared connection and a user explicitly requests regeneration, create/snapshot a new shared summary attempt with its own engine, connection, initiator, budget and usage. Keep original review config/engine/findings/publication immutable and retain previous summary-attempt evidence. This is new shared work, never resumption of native inference. Reject a legacy retry whose effective configuration remains native. Other assessment/review/security retries must likewise reject native execution and must not silently switch the original attempt to API billing.
6. Separate reusable cancellation/coordination from native routes. Move `RunnerBlocked` to a neutral owner before removing its importers; preserve graph-lock and shared-busy behavior. MCP tools import the subscriptions router, so remove native tool registrations selectively while preserving shared tools/consent/provenance.
7. Settle standalone `generate_background` and `generate_summary` jobs as well as active ReviewRun/SecurityScan work. The current helper does not enumerate them. Existing poll/authorization checks cooperate with revocation, but they are not a complete durable retirement settlement. Preserve `partially_published` when cancelling existing reviews; `stop_review`'s default alone does not.

These decisions define tests needed in M1; no cutover or new behavior is claimed. The summary-attempt design must preserve existing shared-origin retry behavior while making the retired-native distinction explicit.
