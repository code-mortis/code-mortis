# PR Code: local delivery and validation

Delivered locally on 2026-10-29 from [checkpoints A–D](pr-code-plan.md). This supersedes the browser entry point in graph Phase 4; it does not change Phase 2's experimental review-enrichment decision or complete Phase 5 production readiness.

## Delivered behavior

**Code** replaces the visible Impact tab and defaults to **Diff**. Reviewers can search and page through changed files, see old/new line numbers and additions/removals, select saved change groups, open immutable finding evidence, and optionally navigate Dependencies, Definitions or Source. Diffs do not require graph enablement, readiness, a parser or retained Git objects. Old `tab=impact` links retain their graph selection; `graph_revision=base` opens merge-base source. New `code_view`, `code_group` and `code_occurrence` parameters preserve view, explanation and evidence selection through reload/back navigation; existing file/page/query parameters and other PR filters remain intact.

The shared search, SearchSelect, pagination, status/tooltips, tabs, code colors and evidence sheet remain the app's visual system. Headers and detail tabs align with the joined file list. Mobile stacks the columns, long paths wrap, and diff/source overflow stays inside the code region. Stored descriptions appear only for the selected group; there is no automatic tour, repeated introduction or new editor framework.

The group selector reuses a completed summary for the exact PR/base/head. It deterministically selects the latest matching result, validates its schema, requires matching saved exclusions and a recorded source inventory, rechecks every input path and group path against current visibility, and checks credential material. A result whose safety cannot be established is withheld. Missing groups do not block All changes and never start generation. Groups explain files, not individual sentences anchored to lines.

Finding placement uses an immutable Occurrence snapshot's canonical path, explicit source SHA and complete line range, plus its ReviewRun base/head pair. Source SHA binds the original or new side; only a range fully present in the displayed diff can be inline. Mutable Finding content and last_seen_run_id do not establish an anchor. Current resolution is returned separately. Older or out-of-hunk findings can also use their latest completed verification at the exact displayed head. The reader validates the bounded saved result and compares every visible cited line with the quoted source; citations spanning omitted context can anchor only on matching displayed lines. Failed, stale, mismatched and oversized verification results never supply a location. Original snapshots and source SHAs remain unchanged, and the preview distinguishes the verification verdict from the current resolution. Repeated occurrences share one marker per finding; old occurrence links still open their original evidence. Only evidence without either reliable anchor remains below the diff. Reading never changes finding resolution.

## Read contract and limits

- Browser-session-only POST `/api/v1/pulls/{id}/code/workspace` bundles the bounded inventory and one selected view; legacy GET `/api/v1/pulls/{id}/code` and POST `/api/v1/pulls/{id}/code/file` remain. These routes live under the existing pulls router and `reviews/code.py`. File requests bind saved base/head, server-resolved merge base and a canonical path. No PAT/MCP scope expansion, new grant, service, worker, dependency or embedding.
- Admission and response boundaries revalidate current membership, repository/installation identity, fresh GitHub access, exclusions and PR revisions. Wrong/moved revisions return 409; revoked access returns 403. Renames retain both paths, and either excluded side withholds the file before counts or pagination. Policy identity participates in the browser query key so a policy refresh cannot preserve an old file response.
- GitHub compare is requested with immutable SHAs and first-page commit pagination. [The provider contract](https://docs.github.com/en/rest/commits/commits#compare-two-commits) supplies at most 300 changed files on that first page; reaching 300 is conservatively incomplete. `previous_filename` identifies renames. An absent patch is **unavailable**, never assumed binary, unchanged or complete.
- The new optional GitHub adapter path streams at most **8 MiB decoded JSON** before parsing. A **20-second elapsed stream budget** is checked between chunks with **five-second I/O timeouts**; existing transient GET handling permits at most two attempts with a one-second delay. Existing authorization calls retain their own timeouts. These are acquisition bounds, not a whole-route latency guarantee.
- Four in-process comparison entries share immutable validated data between diff and graph readers, never credentials or permission decisions. Current exclusions and authorization run on every server read; the GitHub transport reuses bounded process-owned connections with per-request credentials and no cookies. Responses are `no-store`. The mounted Code workspace retains at most 10 content entries / 5 MiB for up to 30 seconds from each validated fetch, with one visible-view refresh and bounded intent prefetch. Leaving Code, account/session change, offline state and access/revision errors clear retained content. Search/groups/pages use the returned inventory locally; navigation controls stay responsive while an uncached selected file loads. Inventory metadata is capped at 2 MiB, with deduplicated group file indexes and an explicit limit state.
- Pages contain **10 files**. The complete fetched patch is credential-checked before a **256 KiB patch** and **2,000 displayed-row** limit. Hunk counts, original/new numbering, additions/deletions, CRLF, Unicode and no-final-newline markers are validated. Malformed content is unavailable; incomplete/count-mismatched or clipped patches remain visibly truncated. Missing provider counts stay unknown, not zero. No implicit repository clone or index is started.
- At most **100 saved occurrences** are returned with an explicit truncation flag. Each sanitized snapshot is at most **32 KiB**, is checked again for credentials and exposes only the evidence fields used by the sheet. Missing or unsafe summary/finding material is withheld. Current code-source checks and graph administrator indexing remain unchanged on their separate routes.

## Review workflow

The [high-priority workflow](pr-code-review-workflow-plan.md) adds automatic reviewed-file checks, Previous/Next navigation with scoped Alt+Up/Down and current open-finding row indicators. Filters combine Not reviewed and With open findings with existing search/groups. A check comes from validated completed/reused file outcomes at the current PR base/head; it does not mean there are no findings. There is no Reviewed checkbox, manual action or new persistence. The diff retains its original natural height with a 70vh maximum and internal scrolling; the viewport-filling experiment was reverted at the user's request.

The browser-only workspace response includes `file_states` parallel to its authorized bounded inventory. Review coverage is validated as a complete, nonoverlapping partition of selected items; earlier, malformed or incomplete file outcomes do not earn a check. Finding counts inspect at most 1,000 bounded immutable occurrences in one batch, using shared credential context and explicit lower bounds/unknown counts when incomplete. Indicators refresh saved evidence before opening the existing sheet. Existing finding actions refresh counts. Both metadata paths reuse authorization, need no graph/model/worker, and never write progress or resolve findings implicitly.

Final workflow verification: **158 selected backend checks**, **76 Code browser checks**, Ruff, regenerated types and build pass. Real local PR #34 shows **46/62 reviewed** with no checkbox and the original bounded diff height restored after feedback. Final timing: **20 warm reads, 957ms p95; 20 cached switches, 19.5ms p95; six idle API calls/minute**. See the [workflow acceptance](pr-code-review-workflow-plan.md#evidence-and-resume) for raw timing artifacts, bound tests, preserved records and local-only limits.
